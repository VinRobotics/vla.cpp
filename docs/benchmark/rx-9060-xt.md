# AMD Radeon RX 9060 XT (ROCm)

`vla-bench` times `predict()` in-process on synthetic inputs. It measures the
engine only: no transport, no simulator, and no claim about task success.

## Test setup

| | |
|---|---|
| Device | AMD Radeon RX 9060 XT, 16 GB GDDR6, RDNA 4 (`gfx1200`, 32 CUs) |
| Host | Intel Core i5-12400F (6 cores, 12 threads), 15.4 GiB RAM. The host also holds an RTX 3060, which ran nothing during the round |
| Power | 160 W board power limit (the default), `power_dpm_force_performance_level` auto, CPU governor `powersave` (intel_pstate) |
| OS | Ubuntu 22.04.5 LTS, kernel 6.8 |
| Driver / toolkit | amdgpu DKMS 6.19.14 / ROCm 7.14.1 (HIP 7.14.60850, rocBLAS 5.5.0, hipBLASLt 1.4.1), AMD clang 23 for HIP, GCC 11.4 |
| Commit | `d0e5d00` (PR #35 merged with main `f464653`) |
| llama.cpp | `b11223` |
| Date | 2026-10-28 07:19 to 08:16 (UTC+07) |
| Build | `HIPCXX="$(hipconfig -l)/clang" HIP_PATH="$(hipconfig -R)"` `-DGGML_HIP=ON -DGPU_TARGETS=gfx1200 -DCMAKE_BUILD_TYPE=Release` (`GGML_NATIVE=ON`) |
| Runtime flags | defaults; the fastest flags per model are in the second table |
| Method | 3 warmups + 20 timed reps per process, 3 processes. The process with the lowest mean is reported, and memory is the peak over all three. |

**Peak VRAM** is the process's VRAM from the amdgpu KFD counters (`/sys/class/kfd/kfd/proc/<pid>/vram_*`, the figure `rocm-smi --showpids` reports), sampled every 0.5 s. **Peak host RSS** is the process's peak resident set (`getrusage`).

### Fastest configuration

We screen each model over these runtime flag sets, then re-run the fastest set
under the full protocol:

- the defaults;
- `--flash-attn` and `--mm-prec default`, alone and together;
- `--weight-dtype bf16` and `--weight-dtype f16`, each alone and with
  `--flash-attn`.

The screen runs 2 warmups and 5 reps in one process per flag set. A flag set
replaces the defaults only if its mean is more than 3% lower, both in the screen
and in the full re-run.

Flash attention, bf16 activations and lower-precision weights can move the
action chunk. Success rates measured at the defaults therefore do not carry over
to these rows.

## Not run

- **BitVLA**: N/A off CUDA. The only published GGUF is int2-packed, and only CUDA builds load it:

  ```text
  vla(bitvla): int2-packed GGUF requires a CUDA build (VLA_BITVLA_CUDA_KERNELS); use the bf16 GGUF for CPU.
  ```

## Notes

- Every model's actions were checked against the CPU build on fixed inputs;
  the numbers are in [backend/rocm.md](../backend/rocm.md#radeon-rx-9060-xt-gfx1200).
- OpenVLA-OFT fits: its BF16 weights take 14.9 GB of the 16 GB. The RTX 3060
  (12 GB) and the i5-12400F host (15.4 GiB) cannot hold it.
- Unlike on CUDA, `--weight-dtype f16` alone gains at most 3% on any model.
  Flash attention is what helps TurboVLA, GR00T N1.5, Evo-1 and SmolVLA.
- SmolVLA's `--mm-prec default` runs its LM GEMMs in BF16 instead of F32 and
  moves the action chunk. An explicit `--weight-dtype bf16` or `f16` is slower
  than the defaults for SmolVLA, because it turns off the F32 widening of the
  LM weights that the default precision uses.
- rocBLAS hands these GEMMs to hipBLASLt by default on gfx1200. Forcing
  `ROCBLAS_USE_HIPBLASLT=0` made π0 3.5x slower (774 vs 222 ms) and GR00T N1.6
  3.2x slower (305 vs 96 ms).
- vla.cpp's fused CUDA nodes and BF16 activations do not exist on HIP, so
  `--act-dtype bf16` was not screened; see
  [backend/rocm.md](../backend/rocm.md#what-runs-on-the-gpu).

## Reproducing

```bash
HIPCXX="$(hipconfig -l)/clang" HIP_PATH="$(hipconfig -R)" \
cmake -S . -B build-rocm -DCMAKE_BUILD_TYPE=Release -DGGML_HIP=ON -DGPU_TARGETS=gfx1200
cmake --build build-rocm -j

# one row, for example SmolVLA
./build-rocm/vla-bench --ckpt smolvla-libero.gguf --images 2 --size 512 --warmup 3 --reps 20
```
