# NVIDIA Quadro T2000 (CUDA)

`vla-bench` times `predict()` in-process on synthetic inputs. It measures the
engine only: no transport, no simulator, and no claim about task success.

## Test setup

| | |
|---|---|
| Device | NVIDIA Quadro T2000, 4096 MiB GDDR6, Turing TU117 (sm_75), no tensor cores; CUDA reports 4095 MiB |
| Host | Intel Core i7-10850H (6 cores, 12 threads), 15.6 GiB RAM visible to WSL2 |
| Power | AC power; GPU power limit 60 W (the default and the maximum) |
| OS | Ubuntu 26.04 LTS on WSL2, kernel 6.18.33.2 |
| Driver / toolkit | 580.92 (WDDM) / CUDA 12.4.131, GCC 13.4.0 with the GCC 15 C++ library path |
| Commit | `4a542ed` plus a local patch that checks device and image compatibility before emitting fused nodes |
| llama.cpp | `b11223` |
| Date | 2026-11-05 15:14 to 16:13 (UTC+07) |
| Build | `-DGGML_CUDA=ON -DCMAKE_CUDA_ARCHITECTURES=75 -DVLA_BUILD_TESTS=ON` (`GGML_NATIVE=ON`); ggml and BitVLA at sm_75, fused and FoldQuant kernels at sm_80 |
| Runtime flags | defaults; the fastest flags per model are in the second table. Fusion and BitVLA MMA disable themselves where the device does not support them |
| Method | 3 warmups + 20 timed reps per process, 3 processes. The process with the lowest mean is reported, and memory is the peak over all three. |

**Device VRAM** is whole-device `nvidia-smi memory.used`, sampled every 0.5 s,
because WSL does not expose per-process device memory. **Host RSS** is peak RSS
from `/usr/bin/time -v`.

### Fastest configuration

We screen each model over these runtime flag sets, then re-run the fastest set
under the full protocol:

- the defaults;
- `--flash-attn` and `--mm-prec default`, alone and together;
- `--weight-dtype bf16` and `--weight-dtype f16`, each alone and with
  `--flash-attn`;
- `--act-dtype bf16 --flash-attn`, for Evo-1.

The screen runs 2 warmups and 5 reps in one process per flag set. A flag set
replaces the defaults only if its mean is more than 3% lower, both in the screen
and in the full re-run. GR00T N1.5 fails at the defaults, so it has nothing to
compare against: its row is the fastest screen configuration that works, with no
speedup figure.

Flash attention, bf16 activations and lower-precision weights can move the
action chunk. Success rates measured at the defaults therefore do not carry over
to these rows.

## Not run

- **GR00T N1.5 at the defaults**: does not fit. It loads 3.31 GiB of BF16
  weights, then a 64 MiB cuBLAS workspace request fails on a 16 MiB pool
  extension. Turing has no fast BF16 path, so ggml promotes BF16 to F32 and needs
  this buffer. Explicit F16 avoids it without shrinking the resident weights.

  ```text
  vla(gr00tn1d5): weights resident in 3.31 GiB (bf16)
  ggml-cuda.cu:109: CUDA error
  CUDA error: out of memory
    current device: 0, in function alloc at ggml-cuda.cu:642
    cuMemSetAccess(start_ptr, reserve_size, &access, 1)
  ```

- **GR00T N1.6**: not attempted. The GGUF is 9.16 GB, about 6 GiB resident
  according to its model card, against 4 GiB here.
- **GR00T N1.7**: not part of the suite.
- **π0, π0.5, OpenVLA-OFT**: not attempted. Their GGUFs are 6.49, 12.59 and
  15.07 GB, and on the RTX 3090 they peak at 5670, 5880 and 14768 MiB of device
  memory ([rtx-3090.md](rtx-3090.md)), against 4096 MiB here.

## Notes

- The old `CUSTOM unsupported` failure came from fused kernels compiled for sm_80
  only. The runtime now checks device and image compatibility before emitting
  fused nodes, and sm_75 uses plain CUDA. BitVLA selects the sm_75 CUDA ladder path
  for its int2 checkpoint, and its LM, ViT and action head activate CUDA before
  prediction.
- VLA-JEPA F16 changes its action chunk: maximum absolute difference 0.0762 and
  maximum RMSE 0.0205 over three fixed inputs. Its speedup says nothing about task
  accuracy.
- Every selected configuration returned finite actions on those three inputs.

## Reproducing

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DGGML_CUDA=ON \
  -DCMAKE_CUDA_ARCHITECTURES=75 -DVLA_BUILD_TESTS=ON \
  -DCMAKE_C_COMPILER=gcc-13 -DCMAKE_CXX_COMPILER=g++-13 \
  -DCMAKE_EXE_LINKER_FLAGS=-L/usr/lib/gcc/x86_64-linux-gnu/15 \
  -DCMAKE_SHARED_LINKER_FLAGS=-L/usr/lib/gcc/x86_64-linux-gnu/15
cmake --build build --target vla-bench vla-server vla_predict_check -j 4

# one row, for example SmolVLA
./build/vla-bench --ckpt smolvla-libero.gguf \
  --images 2 --size 512 --tokens 16 --warmup 3 --reps 20 --markdown
```
